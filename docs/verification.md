# 验证记录与下一阶段

下列是后续验证安排，不是已经通过的测试。本次仓库整理只检查文件完整性、资料一致性和已有 Python 工具的语法。

| 顺序 | 要解决的问题 | 应留下的证据 | 进入下一步的条件 |
| --- | --- | --- | --- |
| 1 | 第二版 CAD 是否完整 | Pack and Go、重建结果、同版 STEP、尺寸/BOM | 无无法解释的缺失引用，版本和实际装配对应 |
| 2 | 电气链路与停止是否明确 | 接线、协议、单执行器测试和失联/停止记录 | 停止路径、方向、限位、单位核对清楚 |
| 3 | 视觉链路是否可复现 | 代码、权重、设备版本、原始随动视频/日志 | 能按 README 重现已报告台架行为 |
| 4 | 四爪是否适配 | 安装照片、开合范围、工具中心、质量和逐级持物记录 | 空载/空碗/目标载荷逐级通过，无明显滑移、碰撞或异常温升 |
| 5 | 定位与自动取放是否可靠 | 相机与手眼标定、逐次成功/失败记录 | 在声明条件内重复取放；失败可停止与恢复 |
| 6 | 底盘低速导航与绕障 | 转向标定、路径与障碍记录、时延/停止距离 | 低速路线可重复，异常观测与通信失联处理得到验证 |
| 7 | 持碗整车任务 | 运输视频、剩余水量、姿态、路线、速度与质量 | 在课程实际工况下验证完整任务 |
| 8 | 速度与动态性能 | 实际测速口径、载荷、加减速及制动记录 | 经前面步骤后逐级确认性能；单独记录高速测试条件 |

不能用供应商极速代替本车速度，用转速回读代替速度闭环，用模型识别代替空间定位，用 CAD 图片代替装配验证。

每份测试记录至少填写：日期、执行人、硬件/CAD 版本、代码提交、环境/载荷、步骤、原始文件位置、结果、失败现象和结论边界。计算项写清输入及假设，测量项写清仪器与单位。

真实测试资料的索引放在 [results/](../results/README.md)。本仓库没有预设成功率、误差或最高速度数字。
