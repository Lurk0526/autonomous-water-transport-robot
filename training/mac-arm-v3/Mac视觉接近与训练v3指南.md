# v0.3：主相机找碗、车辆靠近、腕相机定位后抓取

目标平台为 M2 Pro / 16GB / 原生 arm64 macOS。保留现有 MuJoCo、PyTorch 与 PPO 软件版本；本次加入原有目标碗分割权重、双相机几何定位、移动停车规划、接触修正和 MPS 设备开关。

**这轮的依据是你在 Mac 回传的结果。本机没有重新执行测试、识别、仿真、测速或训练。新增功能目前完成源码静态检查和离线包校验，运行效果、识别率和速度全部留给 Mac 验证。**

## 1. 是否可以扩大训练

大方向继续采用分层控制：识别位置 → 确定性停车与轨迹规划 → 停稳后重新定位 → 抓放状态机 → 必要时小残差 PPO。不要直接把开车、识别与抓取交给一个大策略。

本次回传包 SHA256 与清单82项全部匹配。Mac v2 实测开发93/100、复核179/200（89.5%），尚未达到95%。1024步短训只评3个场景，规则与策略均3/3，不证明有学习收益。

原始诊断显示，40022闭合时臂目标没有变化、跟踪误差原本仅约0.003rad，但硬指节受阻、软垫没接触，闭爪命令还继续推进；夹指越出下限约11mm、碗被弹开后才触发腕关节跟踪超限。40004/40010下降中碗已获得14–21N台面承托，仍继续下压，后续失稳。仿真力未经实机标定，不能直接理解为真实夹力/冲击力。

因此本次不是直接续训旧策略。v3先修正接触控制，再在Mac检查。如果原有四指径向代理在软垫接触前就被硬指节阻住，会明确失败；这可能降低旧版的“成功率”，作用是暴露模型与实物不符。用户已经确认实物能夹起满载650g碗保持2秒，后续应以那条成功动作校准模型。

本轮流程已带 `--large-if-ready`：条件满足时自动先2万步，再根据开发集和异常记录决定是否继续到**累计约10万步**。没有达到条件就保留失败证据，不继续扩训。这个条件是实验安排，不是硬件认证。

## 2. 新增双相机流程

```text
主相机 RGB + 配准深度
  → 既有 target_bowl YOLO11n 分割
  → 从碗外侧边缘的有效深度拟合三维位置与不确定度
  → 多帧稳定确认
  → 枚举停车位置/朝向，检查机械臂完整路径与车体净空
  → 前轮转向车辆连续低速接近
  → 驻车和连续停稳确认
  → 腕相机重新分割
  → 利用已知碗沿半径、台面高度、相机标定进行单目定位
  → 重新检查当前停车位的抓取路径
  → 抓取、试抬、保持、放回
```

默认复用你已有的 `best.pt`，打包为 `assets/vision/target-bowl.pt`。SHA256为 `c402769dabe8f46fd69e01f76054622b15677862fd34e1825618fedc4b9073a6`。没有在本轮重新训练视觉模型。过去它在OpenMV真实图像中有过支架误检；切换到主相机和MuJoCo图像后是否仍准确，需要实际评估，不能把旧准确率套过来。

识别无目标、多个可用目标、过期、轮廓过小/截断、深度不足或几何拟合不可靠时停止接近/等待重新观测。**不使用分割真值、目标ID标签或碗真实坐标替代预测结果。** 场景真值只用于初始化和计算误差指标。暂按单目标与空间稳定性做关联，不宣称已经解决多个相似碗的身份跟踪。

主相机使用米制、与彩色图配准的 optical-Z 深度，从侧壁有效点拟合既有碗外形。黑色反光、水面或纯俯视可能没有可靠侧壁深度，此时会失败，不能拿单个中心深度当碗中心。

腕相机无深度，不能直接把像素当毫米。当前用已知水平平台、碗沿平面及半径的几何约束拟合中心，需要足够可见弧和合理误差；不是任意物体/倾斜碗的通用6D姿态估计。精定位完成后，抓取暂保存该目标估计，抓取过程中不连续跟踪目标；日志明确其测量年龄，绝不会把同一估计伪装成新的视觉帧。

## 3. 停车规划的实际范围

- 候选相对碗位置x为0.16/0.20/0.24m、y为−0.04/0/0.04m，朝向偏移−25/0/25°；仅从这些候选中选择评分较好的可行解，不宣称全局最优或实测最佳抓取成功率。
- 检查预抓、抓取、抬起、下降的分段IK、关节余量、分支连续性、硬指节与台面净空、腕相机视野；并筛选观察姿态到预抓姿态的插值路径。
- 车辆按前轮转向的自行车模型前进，不原地旋转、不瞬移、不倒车。枚举有曲率限制的Dubins路径，以完整矩形车体检查实体台面和圆障碍。
- 控制时加入转向/速度响应、转角变化率和加减速界，再逐10ms采样检查碰撞。终点偏差不能靠无限向前爬行修正，无法到位时停止并报告。
- 规划检查是采样运动学检查，抓取阶段才交接MuJoCo接触动力学；没有完整车辆接触、轮胎打滑、悬挂、液面、障碍识别或动态全局导航。
- 台面位置、尺寸、水平高度是已知场景地图；碗在台面上有独立随机偏移，台面中心不被当成碗位置。障碍几何是已知场景输入，不是已经从道路相机自动建图。

`config/mobile.yaml`里的轴距、车宽、安装偏移、相机姿态、速度和制动参数都是**未实测的仿真假设**。后轴到机械臂平面坐标偏移默认[0.32,0,0]，用于让完整车体停在实体平台外；不能把它写成CAD实测。车辆坐标以**后轴中心**为原点，机械臂模型保留原base_height_m，坐标变换不能重复减去基座高度。

相机位置/朝向是明确声明的仿真标定。腕相机绑定wrist_pitch，即004 roll之前的支架，符合“不随004转”。真实OpenMV内参/手眼和主相机装车外参仍未知，不作为实机控制配置。

## 4. 新接触控制

1. 对向软垫达到既有接触阈值后，锁存实际闭合量；默认预紧0mm，不继续把目标推向32mm。
2. 仅硬指节接触或单指受阻时先停止闭爪，短时确认后仍不满足就明确失败，不靠继续硬顶进入抬起。
3. 下降中发现台面接触和碗底几何符合要求就冻结实际姿态，清除延迟队列里后续的下压指令，再确认承托稳定。
4. 支撑判据使用最低碗表面离台量、真实支撑、倾角与速度，不再用碗body原点距桌面5mm判断。
5. 每个1ms物理步检查四个closure关节的限位/联动误差、臂关节跟踪与非有限数；保存失败前250ms微步窗口、实际驱动力、夹指位置/速度、穿透与接触类型。

保持10mm落点容差、碗底离台30mm、2秒保持等原目标；不加大摩擦、夹力，不关掉硬指节碰撞。`task.contact_supervisor_mode: foam_required`为默认。`any_contact_diagnostic`只用于明确记录的兼容诊断，仍停止受阻闭合，不作为扩大训练的准入证据。

仿真监督器能读接触力，真实设备是否能读触觉/电流尚未提供；精确力只进入监督与日志，不直接给PPO。这个差异和原有MG23径向代理都仍需要实机标定。

## 6. MPS 怎样选择

MPS是Apple GPU上PyTorch的设备；MuJoCo `mj_step`仍在CPU。当前64×64 MLP很小，GPU同步和观测/动作传输可能抵消收益。SB3官方也建议小MLP先用CPU并行，不能承诺MPS加速。

单独测速：

```bash
bash run.sh benchmark --experimental-model --compare-mps --output outputs/v3-benchmark
```

默认CPU2/4/6环境，每次更新固定1536样本，8次更新共12288步、前2次预热；然后用最快CPU的相同并行数比较MPS。关闭GUI、固定评估和TensorBoard写入，分别计时采样与更新；MPS计时段会同步。该测速是吞吐检查，不看奖励判断算法优劣。代理模型若很早触发保护，回合长度会变短，吞吐未必代表未来标定模型的速度。

本轮自动流程只在MPS整体吞吐至少比匹配CPU高10%时选择MPS，否则明确记录CPU更合适。显式设备失败保留错误，不静默切换。手动开关：

```bash
bash run.sh train --experimental-model --device mps --envs 4 --steps 20000 --output outputs/manual-v3-mps20k
```

上面是接口示例。先读本轮training-gate.json；接触守卫普遍拒绝时，不用手工训练绕过问题。`device=auto`不保证选MPS，所以本包只接受明确cpu/mps。

## 7. 训练规模与验收

机械臂扩大训练的前提：至少100次完整场景、成功率≥95%、全部测试完成、原严重故障为零、当前源码/配置/模型哈希一致；复核集同样检查。smoke3/3不算准入。不能放宽关节误差、关闭软垫监督来“通过”。

视觉/移动另检查至少20次真实分割模型结果，识别、停车、精定位各≥95%；它们与机械臂接触是分开的证据，视觉识别通过不等于抓住碗。确定性停车验证可独立进行，不表示要训练端到端开车策略。

按`--large-if-ready`运行且条件通过后：

1. 从头训练20k（实际步数按rollout对齐，日志记录实际数）。
2. 同开发集评估best与final，并检查训练中所有评估的严重异常。
3. 开发性能没有明显退化、异常检查通过，再继续到累计约100k，保留每阶段独立输出。
4. 保持规则基线作对照，按成功优先选模型；best不自动意味着优于规则，final不自动意味着最好。

最后选择策略和配置后才用新盲测50000–50199做一次200次对照，报告Wilson区间和配对差异；本轮默认不消耗。达到190/200仅是点估计≥95%，不代表置信下限达到95%。

PPO仍学习停稳后的小XYZ残差，不学习整车转向或图像特征。双相机流程默认用零残差抓取。若后续v3策略通过检查，可显式将其接入移动流程：

```bash
bash run_mobile.sh evaluate --episodes 20 --seed 70200 \
  --policy outputs/你的v3训练目录/best_model.zip --policy-device mps \
  --output outputs/mobile-with-policy
```

这里视觉几何估计在抓取期间冻结，而单独BowlEnv训练使用模拟带噪目标观测；两者观测分布不同，必须单独评估，不能因为策略静态抓取通过就宣称端到端已迁移。

## 8. 单独看移动和GUI

```bash
bash run_mobile.sh evaluate --episodes 3 --seed 70000 --output outputs/mobile-first3
bash run_mobile.sh gui --episode outputs/mobile-first3/episode-70000 --duration 60
```

`run_mobile.sh gui`在Mac使用mjpython。回放已有结果，不重跑识别或训练。每个episode包含：

- `mobile-episode.json`：各阶段状态、失败原因、设备与权重、假设、误差指标。
- `parking-plan.json`：全部候选、拒绝理由、路径与评分组成。
- `wrist-grasp-screen.json`：新精定位在当前车位的机械臂路径复核。
- `vision/`：每帧预测和光学变换JSON，间隔保存原RGB/预测mask/配准深度；失败帧保存图像，不使用真值mask代替预测。
- `mobile-trace.json`、`mobile-replay.json`、`scene.json`：控制意图、连续车辆与机械臂回放。
- `grasp-episode.json`、`grasp-trace.json`：停稳后抓放与接触守卫证据。

主要失败处理：

| 结果 | 接下来检查 |
|---|---|
| main_vision_acquisition_failed | RGB/预测mask是否正确；是否主相机域差异或反光造成侧壁深度不足 |
| no_feasible_vision_guided_parking | candidate拒绝原因；是否车体/观察姿态穿台、IK不可达、视野不足或路径不可行 |
| forward_path_terminal_pose_mismatch | 连续转向/制动误差，不能改成瞬移终点或原地旋转 |
| wrist_vision_or_precise_grasp_screen_failed | 腕相机遮挡、圆弧不足、标定和碗沿假设、精定位后路径净空 |
| hard_contact_before_foam | 旧指节径向代理在软垫接触前受阻；先补真实开合映射，不增加力硬顶 |
| closure_joint_limit / closure_coupling_limit | 微步夹指位置、约束和接触异常，不等到臂跟踪失控再报 |
| support_missing_after_lower | 碗底实际几何、承托和稳定是否成立；不绕过松爪确认 |

当前视觉运行是同步仿真步：推理期间仿真时钟暂停，记录实际推理墙钟，但没有模拟完整曝光/USB/异步推理/底盘通信延迟。不能把这里的时间戳检查当成真实延迟验证。
