# 小车算法接入：循迹主方案、无标线备用

用户于2026-11-01明确：现场大概率有赛道线，无标线只作为备用；线色暂未确定，先兼容黑线、白线和黄线。当前不需要租GPU。

## 已完成的软件

- `line_tracking.py`：三色候选检测、连续帧确认、路口/多线歧义拒绝、像素路径到已标定地平面的投影，以及主/备用模式选择。缺少底盘或障碍有效状态时默认停车。无外参不能把像素误差当作米或实车转角。
- `parameters.py`：按参数逐项导入带单位、状态和证据哈希的测量记录，保留未提供项，不覆盖原有假设配置。文件校验不代表测量精度已独立验证。
- `ros_monitor.py`：只订阅真实ROS消息和相机输入，检查里程计、IMU、实测转角、感知状态及车体障碍点，保存JSONL和状态快照。不发布底盘运动指令。
- `feedback.py`：拒绝时间戳超前、过期、重放、序列回退、错误坐标系、未知/负协方差、定位突跳和“位姿不变但速度持续报告运动”。分开检查轮速/IMU不一致和不同步。
- `localization.py`：轮速/陀螺仪平面积分、协方差传播、绝对位置校正及离群点拒绝；没有绝对参考会漂移，初始原点任意。当前没有接入真实轮速或IMU。
- `rgbd_audit.py`：逐帧检查真实rosbag的频率、间断、配对、零深度、内参、相机内部TF和深度投影。原始数据库只读。
- `vision_checks.py`：真实RGB-D抽样的ORB匹配与PnP几何筛查。它没有回环、独立位姿真值或车体外参，不作为完整定位系统。
- `obstacles.py`：有实测安装和当前姿态时，构建保守的观测地面网格。未知/无深度/非铺装不自动作为空闲，凸起与负高差覆盖空闲；超出局部平地姿态范围则拒绝输出可用网格。
- `calibration.py`：从“指令+实际速度”日志拟合候选制动参数，不发送动作、不自动写成实车制动保证值。编码器积分会受打滑影响，需要外部距离真值对照。
- `capture.py`、`preflight.py`：有界录制、元数据、可用话题发现、原始流新鲜度检查、验收报告，以及显式请求下最多一次相机服务恢复。

## 运行

在项目根目录：

```bash
# 循迹主方案 + 无标线备用 + 故障/噪声/任务流程
./run_cart_sim.sh

# 查看实时输入，只订阅，不发运动指令
./cart_preflight.sh

# 仅在缺少新鲜相机流且设备存在时，最多尝试一次相机服务恢复
./cart_preflight.sh --recover-camera

# 现场人员把相机带到砖路后录制；手持数据不等于装车数据
./cart_capture.sh --seconds 15 --location field --camera-placement handheld \
  --route-id brick-01 --condition shade
```

完整仿真需要NumPy/OpenCV（本机项目环境已有），不需要ROS或GPU。纯标准库无标线备用可运行 `./run_cart_sim.sh --backup-only`。真实相机录制/监测使用本机已安装的ROS 2和相机驱动，入口脚本自动加载它们。

默认报告：`sim/line_free_cart/output/report.html`；真实输入验收：`sim/line_free_cart/output/integration/report.html`。

参数表为 `config/cart-vehicle-measurements.json`。填写后 `./run_cart_sim.sh --measurements config/cart-vehicle-measurements.json` 自动生成本次仿真配置；原始配置保留。当前真实测量表全部为未知，**没有把0.32m等仿真假设改名为实测值**。

查看已有图片的三色候选（只预览，不驱动）：

```bash
source ./activate_gemini.sh
/usr/bin/python3 -m cart.line_preview \
  --pair work/cart_integration/rgbd-audit-adjusted/sample-pair.npz \
  --rotation 180 --out work/cart_integration/line-preview
```

预处理后像素路径与原始像素路径分别保存。用真实相机原始内参投影时使用 `path_pixels_raw`，并补齐实测外参，不能只旋转RGB而忽略几何。

## 循迹与备用的边界

循迹模式需连续新鲜观测建立信任。短时丢线减速；长时丢线只有在备用定位、路线、底盘和障碍输入可信时才切换无标线模式，否则停车。路口/多条候选不随意选择，先停车，等待现场路线或标记定义。

当前线检测按单条中心线建立基线；若现场采用双侧边界、断续线或特殊站点标记，须据真实样本确认相应线形定义。不能把场景未定义解释成已经支持任意赛道。

闭环循迹仿真使用简化透视渲染的三色线，转向来自图像检测与虚拟相机几何；定位、障碍和终点距离为合成输入。无标线备用扩展了掉头、交叉闭环、长连续弯、窄路、曲线走廊绕障、模型不匹配、制动减弱、冻结位姿、未来时间戳和不确定度增长。

## 仍需实物或现场提供

1. 底盘负责同学提供轴距、车宽、前后悬、转向范围与反馈映射、实际速度/IMU/里程计、STM32协议或现成ROS驱动。
2. 机构和安装确定后提供车体/后轴坐标关系、相机外参、地面高度、三维机械臂模型及关节参数。
3. 现场人员执行下面的采集计划，确认线宽/线形、光照、路口和取放站点标记，并提供可核对的距离/位置参考。
4. 制动和满水表现需要真实闭环记录。软件及候选拟合不能替代刹停距离、承载、夹持和洒水实测。

这些资料不要求用户承担机构改造。缺少时软件保持待接入/待验收状态。Isaac Sim用于后续三维碰撞、接触和传感器仿真；Isaac Lab训练仍未到必须阶段。

## 现场采集计划

每段先录10～15秒，记录路线编号、线色/线宽、相机临时/最终安装状态和光照。初轮可手持检查外观/深度，最终需按装车视角补录。

| 场景 | 检查内容 |
|---|---|
| 直线与左右弯 | 三色中实际使用的线、线宽变化、像素方向及地面投影 |
| 日照、树荫、明暗切换 | 线的置信度、深度有效率和曝光/模糊变化 |
| 砖缝、阴影、落叶 | 不把自然边缘当赛道线或把阴影当障碍 |
| 线短暂遮挡、出画、断续 | 减速、切备用/停车与重新确认行为 |
| 路口、起终点和取放平台 | 明确分支选择和站点成功判定，不能只靠计时 |
| 箱子、路沿、窄通道 | 已知距离参照、障碍/未知区域，以及是否有绕行净空 |
| 颠簸和俯仰变化 | 运动模糊、姿态与地面模型的适用范围 |

同一视频的相邻帧不能拆进训练和测试两边。无标注数据只做数据健康检查；道路/赛道精度需独立标注。单位、坐标、新鲜度及来源检查在所有模式下持续生效。
