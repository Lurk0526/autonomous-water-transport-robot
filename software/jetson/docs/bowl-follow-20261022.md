# 2026-10-22 图像居中跟随优化与实机记录

本次目标：相机随臂运动，让目标碗靠近画面中心；碗停止后完成剩余居中纠偏并保持。
目标点为 320×240 图像的 (160,120)。本轮不执行接近平台、抓取或夹爪开合。

## 控制与实测

本轮已在实际相机安装和姿态下完成 000～004 的双向测量，数据通过方向一致性及条件数检查。
局部图像响应矩阵（行是图像 x/y，列是 000、001、002、003、004，单位 px/实际 P）：

```
[ 1.60756,  0.01973, -0.09067, 0.05338, 0.0 ]
[-0.12403,  0.87988, -1.06862, 1.26049, 0.0 ]
```

矩阵条件数 1.1647。底座、肩、肘、腕共同分配图像纠偏；004 实测对中心的位置响应太小，
分配器将这一列置零。005 是夹爪开合，跟随时保持开度并读回位置。六路均接入通信，
不是用夹爪开合来改变画面中心。标定以实测关节位移为依据，并保存正负向原始帧测量。
在同一局部姿态复用已完成数据时，记录姿态差异，不把未测量的轴当作已通过。

## 已实施的策略

- 用带边界的阻尼最小二乘分配动作，关节限位、窗口、单步和累计行程约束进入求解。
  达到限位的轴不再继续分配动作，其他有效轴承担纠偏。无可用动作时显示 `limited`。
- 偏差大时提高增益，接近中心时降低；默认每轴指令不超过 65 P。
- 原始观测进入横纵各 ±6 px 区域后停止，已经停止时用 ±9 px 外圈重新启动纠偏。
  当前帧居中立即停止，避免等待 EMA 平滑尾部继续移动。没有积分或目标速度外推。
- 相机 ROS 回调只更新最新观测；独立线程独占串口、计算控制并读回位置。反馈查询期间
  相机继续接收新帧，不积压旧图像。反馈完成后用新观测重新规划。
- 一次只查询一个运动轴，避免连续查询五个轴延迟居中/丢目标的停止判断；最近实测位置可短时复用。
- 按完成动作后的实测残差更新方向补偿；小指令无响应时在限定范围内增加补偿。
  普通模式超出反馈容差停止；联调模式允许在局部范围内、方向一致且误差不超过 25 P 时学习变化的负载偏差。超出这些条件仍停止。

实测腕部 `T0600`：起点 P694，目标 P739，发送后 0.359 s 仍为 P694，
0.658 s 为 P702，0.959 s 为 P707。动作存在启动延迟，因此运行配置采用
500 ms 指令时间及 200 ms 反馈等待余量。图像观察和居中/丢目标停止在运动过程中持续进行，
不等这个余量结束才看图像。不能把 50 Hz 控制线程频率说成舵机 50 Hz 完成动作。

## 验证与证据

65 项离线测试通过，覆盖可用轴分配、限位、方向补偿、静止抑振、当前观测即时停止、
相机输入不被慢反馈阻塞、分批反馈、相机停更不重发旧动作、操作员停止锁定和自适应补偿。
测试均不打开实体串口。

含固定局部响应、50 ms 相机延迟和 400 ms 插值的仿真中，首次进入居中区域的时间由
1.40 s 降至 0.92 s；两种策略在最后静止阶段均没有继续发命令。
该仿真没有完整拟合实测启动延迟，数值不是实机速度承诺。

实机新一轮验证：视觉约 18 FPS；已从画面上方位置纠偏至约 (158.7,116.6)，
控制状态 `centered`，最后命令计数为 6，串口仍保持连接等待碗移动。
连续状态证据位于 `work/control-speed-20261022/live-verification.json`；
移动测试另存 `moving-verification.json`，应按其实际状态评估，不预先记为通过。
其他原始标定、动作检查及仿真结果位于同一目录及 `work/bowl-follow/`。

## 使用

```bash
# 同一姿态、标定仍有效且碗可见时准备新目标锁定并启动跟随
./start_bowl_tracking.sh

# 更换姿态或相机安装后：先固定碗，重新进行实体标定并启动
./start_bowl_tracking.sh --calibrate

# 停止跟随、保留视觉
./start_bowl_tracking.sh --stop
```

GUI“停止机械臂跟踪”按钮会锁定停止，重新启动服务后才恢复。
每次运动会话默认 15 分钟，超时及反馈故障退出控制线程、发送停止并释放串口。
目标丢失/数据过期时停止，可在同一目标重新出现后重新积累稳定帧。
关节仍受本轮局部范围限制。平台位置、深度与抓取路径不是本轮控制量。

## 移动测试暴露的问题与最终运行配置

第一轮移动测试被用户判定为“完全不跟随”。当时记录显示多目标判定触发停止，随后
`unexpected_position_after_stop` 故障退出；不能把前面的静态居中说成移动跟随已通过。
后续还捕获了负载偏差变化、刚停止后的回弹和过窄的底座范围，逐项保留原始故障记录。

最终配置改为：底座和腕部优先（权重 1），肩、肘以权重 8 在主轴受限时协同；
普通居中/丢目标只发送正在移动轴的 `$DST:x!`，故障与退出仍发送全局停止。
停止后检查局部绝对范围、相对姿态窗口和单步包络，不要求中断动作停在最终设定点附近。
方向补偿允许更新到 [-60,60] P，且保留方向、位移和软限位检查。短时停止后的不超过
25 P 回弹可依据新实测位置重算指令，不能据此跳过越界或大幅未知运动。

检测出现额外低置信度框或同一碗的高度重合重复框时，依照已锁定中心和框进行关联。
两个可信候选交叉且无法区分时仍停止。初始锁定允许边缘裁切但需唯一高置信目标，
标定仍要求完整、稳定目标。

底座扩展到标定起点约 ±240 P，另受绝对 P1100～1900 范围限制；
肩、肘、腕仍受标定附近的范围约束。每轴相对姿态窗口覆盖它的软限位，避免两个局部窗口
相差几 P 造成无意义的故障退出。完整配置保存在 `work/bowl-follow/current-trial.json`。

厂家本地源码 `work/jibot1-manuals/firmware/src/z_action.c` 的 `parse_action()`
对小于 500 ms 的 PWM 计时额外加 300 ms。最终使用 500 ms 档，避免这个分支；
这不等于已验证所有总线/机械环节都没有额外延迟。

最终一轮已从约 (88,60) 跟随到 (163,114)，运动仍使能，等待用户再次移动验证。
连续记录位于 `work/control-speed-20261022/continuous-final.json`；其最终状态及用户反馈
决定移动验收结果。前面的失败证据没有被覆盖为成功。

## 桌面界面与停止后恢复

桌面图标名称为“机械臂碗跟随”，双击可打开或唤回同一个工作台窗口。
界面打开只恢复相机和识别；绿色按钮为“开始跟踪”，停止后改为“继续跟踪”。
点击绿色按钮会重新锁定画面里的碗、查询六路位置，在之前已验证的绝对范围内建立新会话。
识别不到清晰碗或关节已出范围时显示原因，保持停止。
红色“停止跟踪”同时发送停止请求并关闭控制服务，随后可以再次开启。

本轮修复了严格 shell 启动与 ROS 环境初始化的 `AMENT_TRACE_SETUP_FILES` 未绑定变量冲突。
已通过实际服务的“启动→停止→再次启动→停止”检查，结束保持停止。
桌面入口为 `open_bowl_workbench.sh`，快捷方式安装在桌面和应用程序菜单；
图标重复启动采用单窗口连接，只唤回现有界面，不重复占用相机。
