## 关节与控制链路

| 舵机 ID | 标准爪子版对应部件 | 控制用途 |
| --- | --- | --- |
| 000 | 底座旋转 | 改变水平朝向 |
| 001 | 肩部俯仰 | 与肘、腕共同控制末端位置 |
| 002 | 肘部俯仰 | 与肩、腕共同控制末端位置 |
| 003 | 腕部俯仰 | 调整末端倾角 |
| 004 | 末端旋转 | 调整夹爪绕自身轴的角度 |
| 005 | 夹爪 | 开合 |

这是标准爪子版的结构对应；用户四爪工具的实际安装、开合行程和工具中心尚需核对。

USB → 控制板 CH340 → STM32 UART1 → 总线 UART3 → 各舵机。源码 UART1、UART3 均为 **115200、8N1、无流控**。

### 已核实的指令

以下仅为协议示例，本文档不会执行指令。

| 目的 | 指令 | 实际含义 |
| --- | --- | --- |
| 控制板通信检查 | `$GETA!` | 该版源码回复 `AAA`；不控制电机 |
| 读取控制板配置 | `$DRS!` | 输出 module、bias、preCmd；不提供实时关节位置 |
| 单舵机移动示例 | `#004P1530T1200!` | 004 号移动到绝对 P=1530，耗时 1200 ms |
| 多舵机移动 | `{#000P1500T1500!#003P1000T1500!}` | 多条单舵机命令用花括号包裹 |
| 执行已存动作组 | `$DGT:3-7,1!` | 顺序执行 3 至 7 号动作组一次，具体轨迹依赖已下载内容 |
| 控制板停止 | `$DST!` | 停止动作组，停止 PWM 插值，并向总线发 `#255PDST!` |
| 舵机直接位置查询 | `#004PRAD!` | 舵机协议定义回复 `#004P1500!`，能否经现有 USB 链路收到需验证 |
| 位置控制 | `$KMS:x,y,z,t!` | 此版源码的笛卡尔位置命令，位置单位 mm，时间单位 ms |

单舵机 ID 固定三位，P、T 固定四位。舵机协议 P 范围 500～2500，T 范围 0～9999 ms。这是通信范围，**不是已验证的机械关节安全范围**。

标准 270°模式下，P 改变 30 对应约 4.05°；180°模式下约 2.7°。必须先核对模式和当前起点，不能把绝对 P=1530 当作“相对移动 30”。

该版 STM32 的 UART3 中断把总线接收送进命令解析器；`parse_action()` 内的 `zx_uart_send_str()` 同时向 UART1 和 UART3 发送字符串，USB 会收到命令回显。实体测试中 `#004PRAD!` 后确实收到了 `#004P1501!` 形式的位置回复，可以把它与查询命令回显区分开。`#004PMOD!` 只收到查询回显，尚未取得模式回复。不能把 `$GETA!` 回复或移动命令回显当作实测位置。不得以 `PULK` 释放力矩代替停止。

## 实体小幅测试顺序

1. 枚举 USB 设备并确定控制板端口；不对 Jetson 内置串口盲发命令。
2. 使用 `$GETA!` 检查 STM32 链路，再读取 `$DRS!` 配置。
3. 核对当前姿态、初始位置和实际舵机模式；已有用户确认空载且周围无遮挡。
4. 先选单关节作约 3～4°慢速往返。优先评估 004 末端旋转，避免直接运行未知动作组或同时活动承重关节。
5. 核实实际运动与停止效果，再扩大到其他关节。串口写入成功只能证明命令发送成功，不能独立证明实物运动成功。

### 2026-10-19 实体测试结果

- 用户确认 USB 连接、独立供电、空载、周围无遮挡，且机械臂处于直立状态。
- 重插后枚举到 CH340 `1a86:7523`，端口 `/dev/ttyUSB0`；当前用户属于 `dialout` 组。
- `$GETA!` 得到 `AAA`，`$DRS!` 的 8 个偏差均为 0，preCmd 区输出为 `0xff`。
- 004 号两次起点位置均为 1501。
- 发送 `#004P1521T1200!`，等待后查询得到 1509。位置有变化，但比目标少 12；程序因此中止后续的负向往返。
- 恢复阶段发送 `#004P1501T1500!`，最终查询为 1505，距原起点 4。已发送 `$DST!`，收到对应的 `#255PDST!` 总线停止命令回显。
- 本次只验证小幅试动和位置查询链路，**未通过完整往返的目标跟踪验收**。尚不能确定差异来自舵机死区、机械阻力、模式/比例、反馈精度还是其他原因，不能据此直接扩大运动范围。
- 用户反馈：上述首轮未观察到动作，因此首轮不记为实体试动成功。
- 随后将 004 号目标改为中位附近 P=1560、T=2000 ms，再以 P=1500、T=2000 ms 返回。实测序列 **1506 → 1552 → 1504**，结束后发送 `$DST!`，收到 `#255PDST!` 回显。用户明确确认“这次看到了，转动后回正”。本轮完成了用户要求的单关节小幅运动测试，其他关节未作主动测试。
- 第二轮在标准 270°模式下目标偏移约 8.1°，180°模式下约 5.4°；模式查询尚未取得有效回复，因此这些是协议换算估计，不是实测角度。目标与反馈仍有约数个 P 单位的偏差，不能把这次小幅测试视为精度标定完成。
- 测试中每次打开串口都出现启动输出 `uart1 check ok!#255P1500T2000!`。这提示端口打开可能触发控制板重启及全舵机回中位；核心板原理图存在 CH340K 的 DTR/RTS 控制线路，具体触发关系仍需验证。视觉控制程序应优先保持长连接，查清原因后再设计自动重连，避免重连时意外执行上电动作。
- 日志：`work/jibot1-manuals/usb-probe.log`、`motion-test-004.json`、`motion-004-restore.json` 和 `motion-004-visible-test.json`。日志中的命令回显只证明 STM32 转发；第二轮的实际转动与回正另有用户观察确认。

## 逆运动学实际行为

出厂源码 `USER/z_main.c` 实际调用：

```c
setup_kinematics(110, 105, 75, 190, &kinematics);
```

| 参数 | 源码配置（mm） | 定义 |
| --- | --- | --- |
| L0 | 110 | 地面至 001 轴心的高度 |
| L1 | 105 | 001 至 002 轴心距离 |
| L2 | 75 | 002 至 003 轴心距离 |
| L3 | 190 | 003 轴心至闭合夹爪末端 |

同一行尾注释还残留另一组尺寸，应以实际初始化参数为源码行为依据，以实体测量为标定依据。四爪工具可能改变 L3 和工具中心，不能照抄标准夹爪参数。

`kinematics_move()` 的特点：

- 拒绝 `y < 0`，仅覆盖其前侧工作半空间；底座角计算用 `atan(x/y)`，边界/除零处理不完整。
- 遍历 Alpha=0 至 -135°，从可解姿态中选最负的 Alpha，并非保持固定抓取倾角。
- 只驱动 000～003，004 旋转与 005 开合需要另外控制。
- `src/z_kinematics.c` 把基座角写为 `atan(x/y)`，说明 y 是零基座角时的水平前向、x 是横向；x 在实物上的左右符号还需小幅运动核实。z 是相对于地面的高度。
- `$KMS` 不提供完整六维末端位姿规划，也不做环境碰撞检测。

后续若要固定俯视抓碗角度，需要调整接口支持显式 Alpha，或在 Jetson 求逆解后发送关节目标。进入自动运动前还需要检查有限值、奇异点、可达性、关节边界和路径碰撞。

## 视觉开发承接

原厂颜色跟随：160×120 图像取色块中心，每 50 ms 更新，直接调整 000 与 003。它是图像偏差驱动的跟随。

原厂颜色夹取：识别颜色后执行预存固定动作组。它不测量任意物体三维抓取点，不能直接视为任意位置抓碗实现。

本项目下一阶段建议的实现链路：

```text
相机图像/深度 → 碗的检测与分割 → 稳定抓取点/方向
              → 相机坐标下三维点 → 机械臂基座坐标
              → 工具中心补偿 → 逆解与路径检查 → 串口执行
```

这条链路是项目设计方案，尚未完成相机或实体联调。

需首先补齐：相机实际型号、RGB/深度对齐和内参，固定相机或随臂相机的外参/手眼标定，工作台相对于机械臂原点的高度，四爪工具中心和闭合尺寸，碗的尺寸与允许夹持位置。

首个视觉里程碑可先输出画面叠加的碗轮廓、中心、深度和基座坐标，再接入真实运动。相机未接入时不宣称完成视觉检测；没有外参时不把相机坐标直接送入 `$KMS`。
