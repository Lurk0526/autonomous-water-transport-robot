# 从当前位置启动碗跟随

2026-10-23。用户报告“保持关节 001 的位置已改变”，要求更换机械臂姿态后仍能识别并启动跟随。

旧启动流程绑定昨日肩部位置，姿态不同便退出；直接把旧参考改成当前位置仍会沿用不适用的图像响应矩阵。
现在普通“开始/继续跟踪”会先查询六路实测位置并锁定新鲜目标：

- 姿态与已有局部标定兼容时，使用当前位置作为本次保持姿态和起点。
- 肩、末端旋转改变，或跟随轴离开旧标定区间时，自动在当前姿态重新测量底座 000、肘部 002、腕部 003 的双向响应。
- 测量通过后，生成与当前位置对应的新矩阵、方向补偿及局部范围，再启动跟随；不主动摆回旧姿态。
- 夹爪的新开度直接作为保持值。自动适配时肩、末端旋转、夹爪均不主动运动。

新启动流程不再要求用户手工执行方向标定。适配期间需暂时固定碗，底座探测约 ±30 P、肘部 ±60 P，
腕部正向探测最多 60 P、负向最多 25 P，并尝试返回测量起点；每步检查实际位置、其他关节和图像。
中止时停止，不用失败测量覆盖已有配置。GUI 显示当前适配过程，停止请求也会中断测量并关闭串口。

识别始终独立于关节起始位置；物体需在相机视野内。这里“从当前位置”指有效机械工作区，
并不取消关节行程、失去目标停止、反馈检查或不可观测姿态检查。
沿用当前调试包络：底座 P1100～1900、腕部 P650～1800。
当前姿态模式不再将一次局部标定的 ±90 P 测量邻域当作新的行程限制；
每轴参考窗口覆盖上述包络，规划、单步及反馈检查仍受这些绝对范围约束。
奇异或不一致的图像响应不会启用跟随。
肘部保留已实测的 P1600～2447 指令包络，指令单步最多 65 P；底座与腕部单步最多 100 P，
时间均为 500 ms。分配权重恢复为昨晚的底座/肘/腕 `[1,8,1]`，腕部受限时由肘部接力。

执行 `./start_bowl_tracking.sh` 使用上述自动判断；`--calibrate` 强制从当前姿态重新适配。
原始配置、测试与本次实机记录在 `work/current-pose-follow-20261023/`。

## 本轮验证

离线测试覆盖新肩部姿态触发自动测量、先释放旧串口再重测、
失败保留配置、新姿态生成配置，以及夹爪保持、既有限位、停止和反馈检查。

实机从当前姿态完成双向测量，肩部约 P1449、肘部约 P2347，保持在各自的新位置。
新的 000/003 图像矩阵为 `[[1.771174, 0.034974], [-0.004755, 1.196704]]`，条件数 1.4808。
测量记录为 `work/bowl-follow/calibration-20261023-202506/report.json`。
启动后发出 3 次纠偏，碗中心约 (160.5,121.0)，状态为 `centered`，运动会话仍使能。
这证明当前新姿态的自动适配和静态居中；移动跟随需结合用户实测反馈评估。

用户随后上移测试再次报告限位。记录确认腕部约 P1552，局部指令上界 P1580，
正向偏差约 28 P，导致有效正向余量为 0；这不是腕部机械硬限位的证据。
原始记录保留于 `moving-verification.json` 与 `before-window-fix.json`。

已修复局部测量窗口被误用为机械行程的问题：当前姿态模式使用既有的主轴调试包络，
参考窗口同步覆盖整个包络，验证器拒绝将包络擅自改为协议全行程。
运行时仍逐步按新图像和位置反馈规划，保留方向偏差、单步和累计行程检查。
腕部在下次启动时若已离开原测量姿态超过 90 P，会自动重新测量图像响应。

第一版当前姿态适配只开启底座和腕部，导致用户反馈肘部不参与、速度下降。
已据此恢复底座、肘、腕三轴自动测量和协同；两轴的中间验证不能作为最终三轴验收。

首轮三轴测量中肘部实测正向移动约 67 P，回程存在约 43 P 负载偏差。
原标定器只做一次中间返回，误将指令步长当作实际返回步长，导致后续返回触发局部保护。
已改为每段依据新反馈重新计算，最多 8 段、无实测进展即中止；不扩大原探测窗口。
返回后的补偿最多尝试 3 次，并要求回到起点 10 P 内。
肘部返回时同步采集图像，将已实测的反向位移纳入双向矩阵估计，避免重复死区试探。
