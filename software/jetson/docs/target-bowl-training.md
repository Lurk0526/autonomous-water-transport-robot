# 当前目标碗的识别训练方案

日期：2026-10-19。用户明确要求只识别当前这一个碗。

## 当前观察与基线

- 真实 OpenMV 画面：`work/openmv/target-bowl.png`，320×240 RGB。
- 外观：黑色、有光泽、敞口，碗身能看到环形纹路。当前样本为手持、有室内背景的单一视角。
- 使用官方预训练 `yolo11n-seg.pt` 在 Jetson GPU 测试该帧，碗类别分数约 0.1948，同一区域还出现酒杯类别分数约 0.2501；这是一帧有歧义的基线结果，不是训练后的效果，也不是准确率。
- 原始检测与分割候选保存在 `work/openmv/target-bowl-baseline.json`，叠加结果为 `target-bowl-baseline.jpg`。候选轮廓需人工检查，不能直接当作正确标注。

## 部署位置

沿用当前链路：OpenMV 负责采图，Jetson 执行模型推理，GUI 显示识别结果。训练模型首先部署在 Jetson；Isaac 当前承担图像预处理，目标检测/分割节点还需另外接入。保持当前 OpenMV 4.5.9 采图配置，不把 YOLO 权重直接写入摄像头。

## 数据采集

第一轮可先以 300～500 张有明显差异的目标图像为工程起点，再依据独立测试中的错误补采；该数量不保证任何指定精度。

- 优先采集实际抓取场景：碗放在桌面上，不只拍手持照片。
- 改变距离、画面位置、侧视/俯视角、背景和光照；覆盖黑色反光、深色背景、部分遮挡等情况。
- 分多个独立拍摄批次采集，避免从静止视频连续抽取几百张近乎相同的图。
- 另外采集约 100～200 张对照/背景图作为第一轮起点，包括其他碗、黑色杯子、盘子、空桌面，以及只有手而没有目标碗的画面。
- 有条件加入与目标形状、颜色相似的其他碗，否则无法验证“只识别这个碗”。外观完全相同且无可见标记的不同实物，单凭单目图像可能无法区分；需要识别实物身份时可考虑可见标记。

## 标注与划分

建议使用分割模型：除目标位置外，还能得到可见轮廓，便于后续计算图像中的中心、边缘和抓取候选点。

- 已确定第一版只设一个类别 `target_bowl`；其他碗、黑色杯子、盘子和空桌面作为背景负样本。负样本需人工确认后保存，不能把未标注图片自动当成背景。
- 标注碗的可见轮廓，不把手和背景纳入轮廓，不凭空补出遮挡区域。
- 一只目标碗对应一个实例掩膜。可见内壁、碗底、碗沿属于碗，碗内的食物/遮挡物不属于碗；当前类别不混用仅碗口的标注。
- 简单多边形会填充内部区域。复杂遮挡形成孔洞或分离区域时，当前导出器还不能完整表达，样本先单独复核，不用错误的外轮廓填满来替代正确掩膜。
- 以独立拍摄批次/场景分训练、验证、测试，例如约 80%/10%/10%；相邻视频帧不能同时分到训练和测试。
- 测试集至少覆盖“目标存在”“目标不在”“其他相似碗存在”三种场景。

Ultralytics 分割标签格式：每个实例一行，`class x1 y1 x2 y2 ...`，坐标归一化到 0～1。目录和导出格式见[官方分割数据说明](https://docs.ultralytics.com/datasets/segment/)。

## 训练与验证

利用已有预训练模型微调。下面是数据标注完成后才可运行的起步命令，当前未启动训练：

```bash
source ./activate_project.sh
yolo segment train model=work/models/yolo11n-seg.pt \
  data=datasets/target_bowl/yolo/data.yaml \
  imgsz=320 epochs=80 batch=2 device=0 workers=2 \
  project=work/bowl-training name=target-bowl-v1
```

参数是小显存设备的初始配置，需结合实际训练显存和验证结果调整。把图像放大到 640 不会凭空增加 OpenMV 原始 320×240 图像中的细节。

训练后应检查：目标碗漏检、相似物体误检、轮廓是否包含手、不同拍摄批次表现，以及实时帧率。单帧正确框住不能代替独立测试。

可在验证集选择置信度阈值和连续帧稳定条件，但最终结果需要在未用于调参的测试集上核对。识别通过后，再进行相机标定、桌面坐标映射和机械臂联调；当前识别不输出真实距离或自动运动指令。
