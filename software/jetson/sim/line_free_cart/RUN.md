# 运水小车：循迹主导航与无标线备用仿真

最新主方案为黑/白/黄赛道线循迹，无标线仅为备用。完整套件使用Python 3.10+与本机已有的NumPy/OpenCV，不需要相机、底盘、机械臂、ROS、Isaac或GPU。纯标准库备用加`--backup-only`。真实输入接入和已采集数据见[算法接入说明](../../cart/README.md)。

## 运行与查看

在项目根目录运行：

```bash
./run_cart_sim.sh
# 等价命令：
python3 -m sim.line_free_cart.run
```

打开 `sim/line_free_cart/output/report.html`。页面自带数据，可离线打开；场景下拉框、播放/暂停、速度、时间拖动和结果表均可交互。

输出文件：

- `report.html`：轨迹、速度/加速度/jerk/转角曲线、指标和参数说明。
- `summary.json`：完整指标、配置、随机种子、软件验证范围和源码 SHA256。
- `traces/*.csv`：全部控制采样，不是页面抽样；包括命令、实际模拟状态、输入年龄、紧急停车与阶段。
- `tests.txt`：独立几何检查、闭环行为和故障测试日志。
- `config.snapshot.json`：本次运行采用的参数，不会跟随之后的配置编辑改变。

需要 HTTP 访问时：

```bash
python3 -m http.server 8767 --bind 127.0.0.1 --directory sim/line_free_cart/output
```

然后访问 <http://127.0.0.1:8767/report.html>。直接打开 HTML 不需要启动服务器。

可选参数：

```bash
python3 -m sim.line_free_cart.run --out /tmp/cart-sim-result
python3 -m sim.line_free_cart.run --config sim/line_free_cart/config.json
python3 -m unittest discover -s tests -p 'test_line_free_cart.py' -v
```

`--quick` 跳过 27 组敏感性场景，`--skip-tests` 跳过测试；报告会明确标记未运行，正式记录应使用默认完整命令。

## 已实现的算法

1. 后轴中心为原点的前轮转向运动学模型：`yaw_rate = v * tan(steer) / wheelbase`。包含转角、转角变化率、假设转向滞后，以及速度响应、正常加速度和 jerk 限制。它不是差速车，不能原地转向。
2. Pure Pursuit 跟踪软件航点，结合曲率限制速度，接近终点提前减速。全程没有地面赛道线。路线和定位是已提供的输入；未在本轮实现真实定位或自动建图。
3. 定位与障碍数据分别延迟，指令另有独立延迟。定位加入固定种子的高斯噪声；检测过期、冻结时间戳、突跳、非法值和过大的不确定度。
4. 矩形车体与圆形障碍的几何检查，包含前后悬和余量；停车距离考虑延迟预算与假设制动能力。紧急停车优先于舒适 jerk 限制，相关数据单独标记。
5. 已知道路走廊内的局部绕障：在直线与曲线走廊上枚举两侧平滑偏移候选，检查曲率、原始道路边界和车体几何。新障碍进入感知范围时允许重新搜索；没有可行候选就停车。暂不支持任意场地的全局规划或预测移动障碍。
6. 将现有 `sim/bowl_transport/flow.py` 监督器接到运行中的车辆模型和明确标注的机械臂模拟反馈。车辆到站并停稳后才能抓放；反馈缺失会停在对应阶段直至超时，运输中夹持证据丢失会保持夹爪并制动车辆。
7. 同距离、同耗时的三角速度与余弦速度比较，同时报告平滑曲线更高的峰值加速度，不只选择有利指标。

## 实验矩阵

10个循迹主方案场景：三色直线、黑线S弯、白线左弯、黄线右弯、短时遮挡恢复、长时丢线切备用、备用不可用时停车、路口标记不明确时停车。循迹转向来自合成RGB检测和虚拟相机几何，没有把真实相机未测外参替换成仿真值。

38个无标线备用场景：初版22项，加掉头、交叉闭环、长连续弯、窄路S弯、转向/轴距不匹配、制动能力下降、障碍与指令延迟、未来时间戳、冻结位姿、不确定度增长、启动缺输入、短时误检、弯道/S弯绕障和弯道净空不足。

4 个任务场景：正常取放、缺少抓取证据、缺少承托证据、运输中丢失夹持证据。正常完成与故障保持分别统计；不能把“符合预期的停车”记作完成运输。

27 个敏感性组合：位置噪声 0 / 2.5 / 5 cm × 定位和指令各自延迟 0 / 0.12 / 0.25 s × 3 个固定随机种子，使用同一条 S 弯。它们只验证所列假设，不能变成实车可靠性百分比。

另保留 1 个碰撞反例：障碍直接出现在车体内，真值检查应发现碰撞。反例不计入成功导航数量。

## 参数和证据来源

`config.json` 内轴距 0.32 m、车宽 0.30 m、速度上限 0.55 m/s、紧急减速度 0.65 m/s²等，**全部是仿真假设，不是本车参数或实车速度建议**。车体实际参数保留 `null`，后续按实测替换。

道路走廊、路线、障碍、定位均为合成场景。控制器只读取已送达的合成观测；独立的碰撞/越界检查使用仿真真值。矩形车体按时间子步、局部路径按距离采样检查，不是连续几何形式化证明。路线终点是停车目标而非实体墙，道路在端点沿切线延续车身检查所需距离；实体端墙应作为障碍单独建模。

任务模拟反馈的抓住、承托、松脱、目标坐标、承载等信号是接口夹具，不是视觉/力学结论。任务超时在本模块分别设为行驶 120 s、静止作业 8 s，不修改原有监督器和实体配置。任务用直接模拟状态反馈，导航矩阵另行检查传感器延迟。

当前没有物理水。平滑速度、低加速度等只是候选运动条件；实际洒水质量始终为 `null`。模型不含颠簸、轮胎滑移、悬架、真实制动和三维抓放，不能宣称已经验证室外满水运输。

## 是否租 GPU

本轮无需租赁。下一阶段需要最终底盘/机械臂/夹爪几何、关节轴和限位、碰撞形状、质量惯量与传感器位置，然后才值得用 Isaac Sim 检查三维运动、接触和相机。先按小时验收场景和驱动，不先开长时训练。

Isaac Lab 用于需要训练的策略；本轮确定性基线已可建立，尚没有必须训练才能解决的已测缺口，也没有可训练的最终机器人资产。因此没有启动强化学习任务。物理液体、满水溢流与称重仍需专门建模及实测对应，不能凭 Isaac 软件可启动就认定具备。

算法与底盘/机械臂的后续对接约定见 `INTERFACES.md`。
